# 门店客户端独立安装包改造说明

> 适用版本：仁和堂专用远程工具 1.5.1（定制版）
> 目标：把原先「人工拷贝配置文件 + 便携运行」的方式，改造成**一键安装、配置随包分发、
> 首次启动自引导**的独立客户端。

---

## 一、改造前的现状（问题清单）

### 1.1 配置文件靠人工拷贝

| 项 | 改造前 |
|---|---|
| 配置文件 | `deploy/store_sync.json` |
| 放置位置 | 人工复制到 `C:\Program Files\RustDesk\` |
| 含密钥 | `adminToken` 是**永久**管理员令牌，泄露即可改全公司设备别名 |
| 出问题 | 漏拷/拷错 → 门店名同步功能静默失效，界面无提示 |

### 1.2 产物其实是「便携版」，不是安装包

这是最容易被忽略的一点。当前工作流产出的文件名是：

```
rustdesk-1.5.1-x86_64.exe
```

而 RustDesk 判断「是否走标准安装流程」的依据**只是文件名**：

```rust
// src/common.rs
pub fn is_setup(name: &str) -> bool {
    !config::is_disable_installation() && name.to_lowercase().ends_with("install.exe")
}
```

`rustdesk-1.5.1-x86_64.exe` 不以 `install.exe` 结尾 → **不触发安装**。双击后
packer 把载荷解压到 `%LOCALAPPDATA%\`，直接从那里运行：

- 没有安装向导，用户不知道装到哪
- 没有注册表卸载项 → 控制面板里**卸载不了**
- 没有开始菜单/桌面快捷方式
- 没有 Windows 服务（开机自启、无人值守远程）
- 程序文件在 `%LOCALAPPDATA%`，**依赖「原部署环境」**，换机/重装即失效

> 上游 `build.py` 里其实有正确的命名：
> `os.rename('./rustdesk_portable.exe', f'./rustdesk-{version}-install.exe')`
> —— 定制版工作流绕开了这一步，导致产物退化成了便携版。

### 1.3 门店名无处可查

门店名称只存在于 `RustDesk2.toml` 的一个 option 里，技术员在客户端界面看不到
「这台机器是哪家店」。

### 3.2 门店机上（运行时）

| 路径 | 内容 | 写入者 | 说明 |
|---|---|---|---|
| `C:\Program Files\RustDesk\` | 程序 + **出厂配置** `store_config.json` | 安装包 | 随安装分发，**只读** |
| `%APPDATA%\RustDesk\config\store_user_config.json` | **用户配置**（门店名等） | 客户端 | 用户可写，跨升级保留 |
| `%APPDATA%\RustDesk\config\RustDesk2.toml` | RustDesk 自身配置 | 客户端 | 与用户配置**同层** |
| `HKLM\...\Uninstall\RustDesk` | 卸载项 | 安装包 | 控制面板 → 程序和功能 |
| `%PROGRAMDATA%\...\Startup\仁和堂专用远程工具 Tray.lnk` | 开机自启 | 安装包 | 计划任务/启动项 |

> **为什么用户配置不写在安装目录？**
> `C:\Program Files` 普通用户**没有写权限**。若把门店名写在那里：
> - 界面进程（非管理员）保存必失败
> - 失败后用户填的门店名丢失，下次启动又要重填
>
> 所以用户配置一律写 `%APPDATA%`，安装目录只放只读的出厂配置。
> 这样**安装目录无写权限时程序仍可正常保存配置**（要求 4）。

## 四、配置分层与容错

### 4.1 两层配置

| 层 | 文件 | 位置 | 生命周期 |
|---|---|---|---|
| **出厂配置** | `store_config.json` | 安装目录（exe 同级） | 随安装包分发，只读 |
| **用户配置** | `store_user_config.json` | `%APPDATA%\RustDesk\config\` | 用户填写，持久保存 |

**读取优先级：用户配置 > 出厂配置 > 内置默认值**（逐字段回落）。

举例：出厂配置带 `adminToken`，用户配置只填了门店名 →
门店名取用户配置，令牌仍从出厂配置取，两者互不覆盖。

> **为什么用户配置放在 `%APPDATA%\RustDesk\config\` 这一层？**
> Rust 侧 `Config::path()` 经 directories_next 落在
> `%APPDATA%\RustDesk\config\`，`RustDesk2.toml`、`RustDesk_local.toml`
> 等配置文件都在这一层（已在本机实测确认）。
> 放在同一层有两个好处：
> 1. 与 RustDesk 自身配置**同处一地**，卸载/清理逻辑一致，不会出现
>    「RustDesk 配置被清掉了、我们的门店名还留着」的错位；
> 2. 内部标识 `APP_NAME` 恒为 ASCII 的 `"RustDesk"`（品牌显示名
>    「仁和堂专用远程工具」只用于窗口标题、快捷方式、卸载项等**对外可见**
>    文案，不参与路径），因此这个路径是稳定的。
>
> **首次启动弹窗的触发条件**（重要，刻意不看「出厂配置是否存在」）：
> - 用户配置里 `configured == true`，或用户配置里已有门店名 → **不弹**
> - 出厂配置里预置了门店名 → **不弹**
> - 其余情况（首次运行 / 用户配置丢失）→ 弹窗
>
> 之所以**不**把「出厂配置缺失」当作弹窗条件：那样的话安装包分发不完整时
> 会**每次启动都弹窗**，程序就没法正常用了。出厂配置缺失时改为在弹窗内
> 给出提示、并允许手工填写 API 地址与令牌，主界面徽标也会显示
> 「未检测到出厂配置」。

### 4.2 兼容旧版

旧版 `store_sync.json` 仍会被读取为出厂配置，升级不丢配置。

### 4.3 异常处理

| 异常 | 行为 |
|---|---|
| 安装目录无写权限 | 用户配置转写 `%APPDATA%`；出厂配置只读不需写 |
| `%APPDATA%` 也不可写 | 依次退到 `%LOCALAPPDATA%\RustDesk\config\` → exe 同目录；全失败则弹窗**明确报错**并显示目标路径 |
| 出厂配置缺失（安装包没带） | 首次启动弹窗提示「未检测到出厂配置」，可手填 API 地址与令牌 |
| 用户配置损坏（非法 JSON） | 忽略该文件，回落到出厂配置，程序照常启动 |
| 配置文件读取失败 | 捕获异常 + `debugPrint`，**绝不因配置问题导致程序起不来** |
| 令牌为空 | 同步功能返回明确错误「未配置 adminToken（出厂配置未随安装包分发）」 |

## 五、打包配置调整点

### 5.1 产物命名（关键）

```diff
- mv ./target/release/rustdesk-portable-packer.exe ./SignOutput/rustdesk-${VERSION}-x86_64.exe
+ mv ./target/release/rustdesk-portable-packer.exe ./SignOutput/rustdesk-${VERSION}-install.exe
```

**必须以 `-install.exe` 结尾**，否则不触发标准安装（`is_setup()` 判定）。
这一步同时带来：安装向导、注册表卸载项、快捷方式、Windows 服务。

### 5.2 出厂配置注入

新增构建步骤 `Prepare store config (随包分发)`：

```bash
if [ -n "$STORE_SYNC_CONFIG_B64" ]; then
  echo "$STORE_SYNC_CONFIG_B64" | base64 -d > ./rustdesk/store_config.json
elif [ -f ./deploy/store_config.example.json ]; then
  cp ./deploy/store_config.example.json ./rustdesk/store_config.json
fi
```

要点：
- 配置放在 **`./rustdesk/`**（payload 根目录），`generate.py` 会把整个目录
  打包进载荷，安装时随 XCOPY 一起落到安装目录 —— **无需任何额外的复制逻辑**
- `adminToken` 存放在 **GitHub Actions Secret** `STORE_SYNC_CONFIG_B64`
  （libsodium sealed box 加密存储），**不进仓库、不进构建日志**
- 构建日志只打印键名与 `has_token: true/false`，不打印令牌值
- Secret 缺失时回落到仓库内**不含令牌**的模板，构建不中断，客户端首启提示补齐

### 5.3 配置为什么会自动落到安装目录（无需额外复制代码）

这是本方案能省掉「人工拷贝」的关键机制，已逐行核实：

| 环节 | 代码位置 | 行为 |
|---|---|---|
| 打包 | `libs/portable/generate.py` | `os.walk('.')` 遍历 payload 目录**全部文件**，逐个 brotli 压缩写入载荷。放在 `./rustdesk/` 根下的 `store_config.json` **自动被打进去**，无需改打包器 |
| 安装拷贝 | `src/platform/windows.rs` → `copy_raw_cmd` | `XCOPY "<exe所在目录>" "<安装目录>" /Y /E /H /C /I /K /R /Z`，`/E` = 复制**所有子目录**，整个目录树原样落位 |
| 安装注册 | `install_me` | 写注册表卸载项、开始菜单/桌面快捷方式、Windows 服务（开机自启） |
| 卸载清理 | `get_uninstall` | `rd /s /q "<安装目录>"` 删除整个安装目录（含出厂配置）+ 删注册表项 + 删快捷方式 |

> 因为拷贝的是**整个目录树**而不是逐个文件，所以将来 payload 里再增加任何
> 需要随包分发的文件（如证书、驱动、配置），都会自动落到安装目录，
> 不需要改任何 Rust 代码。

### 5.4 令牌轮换

改完 `deploy/store_config.json` 后重新设置 Secret：

```powershell
$b64 = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes((Get-Content deploy\store_config.json -Raw)))
# 然后用 GitHub API 更新 secret（需 libsodium 加密），或直接在 Settings → Secrets 里改
```

## 六、使用与部署流程

### 6.1 门店端（技术员操作）

1. 拿到 `rustdesk-1.5.1-install.exe`
2. 双击 → 安装向导 → 默认装到 `C:\Program Files\RustDesk`
   - 勾选「创建开始菜单快捷方式」「创建桌面快捷方式」
3. 安装完成，程序自动启动 → **首次启动弹出「门店信息配置」窗口**
4. 填写**门店名称**（如 `仁和堂沂蒙路店`）→ 点「保存并同步」
   - 门店名写入 API 服务器的「设备管理」与「共享通讯簿」
   - 弹窗提示 `设备管理 ✓ 通讯簿 ✓ 服务器实际值: 仁和堂沂蒙路店`
5. 以后启动**不再弹窗**（配置已持久化）

### 6.2 卸载

控制面板 → 程序和功能 → 仁和堂专用远程工具 → 卸载。
（注册表卸载项由安装包写入，卸载时清理服务、快捷方式、安装目录。）

> 注意：卸载**不删** `%APPDATA%\RustDesk\config\store_user_config.json`
> （与 Windows 惯例一致，用户数据保留）。重装后门店名仍在，
> 需要重填时到 设置 → 门店 修改。

### 6.3 批量部署（IT 批量下发）

```powershell
# 静默安装（RustDesk 原生支持）
& "$env:ProgramFiles\RustDesk\rustdesk.exe" --silent-install
```

### 6.4 技术员侧排查

| 现象 | 排查 |
|---|---|
| 没弹配置窗口 | 设置 → 门店 手动填；或检查 `%APPDATA%\RustDesk\config\store_user_config.json` |
| 弹窗提示「未检测到出厂配置」 | 安装目录缺 `store_config.json`，需重新分发安装包 |
| 提示「保存失败」 | 检查 `%APPDATA%` 写权限；弹窗会显示实际目标路径 |
| 门店名没同步到服务器 | 检查客户端「API 服务器」设置；主界面徽标会显示「已同步至公司服务器」 |
| 主界面看不到门店名 | 门店名为空时徽标自动隐藏（不占位、不干扰界面） |
