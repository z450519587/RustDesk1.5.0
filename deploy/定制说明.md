## 二、品牌化设计原则

**显示名与内部标识分离**，这是本次改造最关键的一条约束：

| 类别 | 取值 | 用途 |
|---|---|---|
| 品牌显示名 | `仁和堂专用远程工具`（`APP_BRAND_NAME`） | 窗口标题、界面文案、托盘气泡、通知标题、快捷方式名、卸载项、服务显示名、桌面项、图标 |
| 内部标识 | `RustDesk`（`APP_NAME`，ASCII） | 安装目录、可执行文件名、服务名、配置/日志目录、IPC 命名 |

原因：内部标识一旦改成中文，门店既有设备上的安装路径、服务名与 ID 都会变，
升级后会丢 ID、连不上，且老版本卸载脚本失效。因此内部标识保持原样，只对外可见部分做定制。

### 覆盖到的位置

- `libs/hbb_common/src/config.rs` —— `APP_BRAND_NAME` 常量定义（品牌名唯一来源）
- `src/common.rs` —— `get_app_display_name()`，对外提供显示名
- `src/lang.rs` —— 界面文案中 "RustDesk" 统一替换为品牌名
- `src/flutter_ffi.rs` —— `main_get_app_name` / `main_get_app_name_sync`
- `src/flutter.rs` —— 原生窗口标题（须与 Flutter 侧 `setTitle` 一致，否则单实例
  检测的 `FindWindowW` 失效）
- `src/tray.rs` / `src/core_main.rs` —— 托盘与系统通知标题
- `src/platform/windows.rs` —— 快捷方式、卸载项、服务显示名、消息框标题
- `flutter/windows/runner/Runner.rc` —— `FileDescription` / `ProductName`
- `flutter/android/.../AndroidManifest.xml`、`flutter/ios/Runner/Info.plist`
- `res/rustdesk.desktop`、`res/rustdesk-link.desktop`

## 三、权限策略

**目标**：界面不提权、不弹 UAC、不打断用户；只有后台服务以最高权限运行。

| 进程 | 权限 | 落实方式 |
|---|---|---|
| 界面 / 托盘 | 普通用户（asInvoker） | `res/manifest.xml` 与 `flutter/windows/runner/runner.exe.manifest` 中 `requestedExecutionLevel level="asInvoker"` |
| 后台服务 | LocalSystem（最高权限） | `sc create ... obj= LocalSystem`，由 Windows 服务管理器拉起并开机自启 |
| 需要提权的动作 | 按需弹 UAC | 程序自身通过 `ShellExecute "runas"` 拉起提权子进程（如安装、写 Program Files） |

服务可靠性：

```
sc failure {app_name} reset= 86400 actions= restart/5000/restart/15000/restart/60000
```

即服务连续失败后按 5s / 15s / 60s 三级间隔自动重启。

**开机自启**：不再依赖需要提权的「启动」目录快捷方式（asInvoker 下无法写
`ProgramData\...\Startup`），改用**任务计划程序 → 以最高权限运行**托盘程序，
实现无弹窗、无 UAC 打扰的静默自启。配置脚本见
`deploy/deploy_silent_autostart.ps1`。

## 四、更新提示禁用

关闭了全部版本检查路径，确保不出现任何更新提醒：

| 位置 | 处理 |
|---|---|
| `src/common.rs` `check_software_update()` | 直接返回，不查询版本服务器 |
| `src/common.rs` `do_check_software_update()` | 空实现，不设置 `SOFTWARE_UPDATE_URL` |
| `src/updater.rs` `manually_check_update()` | 不再发送 `CheckUpdate` 消息 |
| `src/updater.rs` `start_auto_update_check()` | 不再启动后台检查线程 |
| `flutter/lib/common.dart` `checkUpdate()` | 移除事件注册与 URL 拉取 |
| `desktop_home_page.dart` | 隐藏更新帮助卡片 |
| `desktop_setting_page.dart` | 移除「启动时检查更新」「自动更新」选项 |
| `mobile/connection_page.dart` | 移除「下载新版本」按钮 |
| `mobile/settings_page.dart` | 移除「启动时检查更新」开关 |

## 五、构建与部署

| 文件 | 用途 |
|---|---|
| `deploy/build_rht.ps1` | 一键构建（环境体检 → 镜像配置 → vcpkg → 调用 `build.py --flutter` → 产物校验） |
| `deploy/Windows编译指南.md` | 详细的机器准备要求、vcpkg 三条准备路线、应急上线方案 |
| `deploy/deploy_silent_autostart.ps1` | 静默自启与权限配置（任务计划程序） |

产物：`target\release\rustdesk.exe`

构建要点（本机不具备出包条件的原因与绕行方案见编译指南）：

- Rust 1.99.1（rustup 走 `rsproxy.cn` 镜像）
- crates 源 → `rsproxy.cn` 稀疏索引
- Flutter 3.24.5 + `pub.flutter-io.cn` 镜像
- vcpkg 需在可访问 GitHub 的机器上准备，或将 `installed` 目录整体拷入

## 六、验证要点

构建完成后建议逐项确认：

1. 窗口标题、任务栏、托盘气泡、桌面快捷方式、开始菜单卸载项均显示
   「仁和堂专用远程工具」，且窗口标题与托盘气泡一致（否则单实例检测失效）
2. 双击图标无 UAC 弹窗，界面以普通权限打开
3. 服务已创建且为自动启动，`sc qc <服务名>` 显示 `SERVICE_START_NAME: LocalSystem`
4. 界面中不出现任何更新提示、更新按钮或「自建服务器」引导
5. 托盘图标与可执行文件图标为新 logo
6. 客户端 ID 可正常获取，能与门店其他设备互连
