# 门店名称同步功能 · 部署与使用说明

> 适用版本：仁和堂专用远程工具 1.5.1（定制版）
> 目标：门店机器安装后，手工填写一次门店名称，该名称即同步到公司 API 服务器的
> **「设备管理」** 与 **「共享通讯簿」**，远程技术员看到的是「仁和堂XX店」而不是一串 ID。

---

## 一、整体原理

```
门店电脑（客户端）
  │  设置 → 门店 → 填名称 → 点「同步到服务器」
  │  从 exe 同目录的 store_sync.json 读取 API 地址 + 永久令牌
  ↓
API 服务器（lejianwen/rustdesk-api，192.168.100.190:21114）
  ├─ POST /api/admin/peer/update          → 写「设备管理」别名
  └─ POST /api/admin/address_book/update  → 写「共享通讯簿」别名
  ↓
回读校验：再 GET 回来比对，确认中文没乱码
```

**关键设计**：令牌不写死在程序里，而是放在 `store_sync.json`，随时可换、可撤。
客户端 exe 升级、换机器，都只需要把这个 json 放到 exe 同目录。

## 二、部署步骤（每台门店机）

### 第 1 步：放入配置文件

把 `store_sync.json` 复制到 **客户端 exe 所在目录**（与 rustdesk.exe 同级）：

```
C:\Program Files\RustDesk\
    ├─ rustdesk.exe
    └─ store_sync.json      ← 放这里
```

文件内容（每台机器都一样，直接复制即可）：

```json
{
  "apiServer": "http://192.168.100.190:21114",
  "adminToken": "971f5a924fa1e3fc9f1e3ab3bb362fb3",
  "addressBookUserId": 1,
  "addressBookCollectionId": 1
}
```

> ⚠️ 这个文件相当于一把「钥匙」，请勿外传、勿放进网盘共享目录。
> 门店内网使用，但仍建议限制文件读取权限。

### 第 2 步：确认客户端已连上公司服务器

客户端 **设置 → 网络 → ID 服务器 / 中继服务器 / API 服务器** 填：

| 项 | 值 |
|---|---|
| ID 服务器（中继） | `192.168.100.190` |
| 中继服务器 | `192.168.100.190:21117` |
| API 服务器 | `http://192.168.100.190:21114` |

> 客户端「API 服务器」必须**带 `http://`**，否则客户端拼出的 URL 无效。
> （客户端自身的兼容性由程序处理，但这里填对最省事。）

连上后，在 API 服务器的「设备管理」里应能看到这台机器的 ID。

### 第 3 步：填写门店名称并同步

1. 打开客户端 → **设置 → 门店**（新增的标签页）
2. 输入框里填门店名，例如 `仁和堂沂蒙路店`
3. 点 **「保存到本机」** —— 先存一份在本地（换网络时也能显示）
4. 点 **「同步到服务器」** —— 写入 API 服务器
5. 弹出结果提示：

```
设备管理 ✓   通讯簿 ✓   服务器实际值: 仁和堂沂蒙路店
```

看到 **「服务器实际值」** 就是你填的名字，说明中文已正确落库。

> 若提示「服务器实际值」是 `???` 或 `��`，说明编码异常，请截图反馈。

## 三、批量部署建议

### 方案 A：随安装包分发（推荐）

在制作静默安装包时，把 `store_sync.json` 一并放进安装目录：

```
install.exe
rustdesk.exe
store_sync.json
```

门店装完即具备同步能力，无需额外操作。

### 方案 B：门店机脚本批量配置

用 `sync_store_name.ps1` 可在任意门店机直接写名称（不走客户端 UI）：

```powershell
cd <部署目录>
.\sync_store_name.ps1 -StoreName "仁和堂沂蒙路店"
```

脚本会自动读取本机 RustDesk ID（从 `%APPDATA%\RustDesk\config\RustDesk2.toml`），
依次写「设备管理」「共享通讯簿」，最后读回校验并输出：

```
========== 结果 ==========
设备管理 : 成功
共享通讯簿 : 成功
中文编码 : 通过
```

> **注意**：脚本与客户端功能重叠。日常用客户端 UI 即可；脚本适合批量初始化或
> 客户端界面出问题时兜底。

## 四、常见问题

### Q1：提示「设备管理里找不到本机 ID」
客户端还没连上公司 API 服务器。先按「第 2 步」配好服务器地址，
客户端上线后（能出现在 API 服务器设备列表里）再同步。

### Q2：提示「未配置 adminToken」
`store_sync.json` 没放到 exe 同目录，或文件名写错了（必须是 `store_sync.json`）。

### Q3：中文变成 `???` 或 `��`
- 若是**用脚本**同步：脚本已修复（PowerShell 5.1 默认按 ASCII 编码中文所致），
  请从最新版仓库重新取 `sync_store_name.ps1`。
- 若是**用客户端**同步：客户端以 UTF-8 发送，正常不会乱码；请截图反馈。

### Q4：改了名称，要重新同步吗？
要。改名后需再点一次「同步到服务器」，否则服务器上还是旧名。

### Q5：令牌失效了怎么办
令牌是永久的（到期时间被设到 9999 年），正常不会失效。
若怀疑泄露，可执行 `deploy/store_sync_token.sql` 重新造一个，并更新 `store_sync.json`。

## 五、文件清单

| 文件 | 作用 | 是否需要分发到门店 |
|---|---|---|
| `store_sync.json` | API 地址 + 永久令牌（**含密钥**） | ✅ 需要（放 exe 同目录） |
| `store_sync.example.json` | 配置模板（不含真实令牌） | ❌ 仅开发参考 |
| `sync_store_name.ps1` | 门店名同步脚本（含读回校验） | 可选（批量/兜底用） |
| `get_admin_token.ps1` | 登录取临时令牌（配 SQL 改永久） | ❌ 仅管理员 |
| `store_sync_token.sql` | 把令牌过期时间改到 9999 年 | ❌ 仅管理员 |
| `probe_api.ps1` | 探测正确的 API 地址与登录路径 | ❌ 仅排障用 |
