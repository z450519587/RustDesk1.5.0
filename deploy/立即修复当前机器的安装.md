# 立即修复当前这台机器的安装（不需要等新包）

## 问题

`C:\Program Files\RustDesk` 里只有 16 个文件，**一个子目录都没有** ——
`data\`、`drivers\` 都不在。

Flutter 的 runner 找不到 `data\app.so`，客户端启动 0.9 秒就以退出码 1 结束，
界面永远不出现；服务还在跑，所以任务管理器里能看到进程 —— 这就是
「后台进程有，但是没有界面」。

缺的这几个是从 `%LOCALAPPDATA%\rustdesk\`（安装包的解压目录）复制过去的。
**源目录是完好的**，直接补拷就行。

## 步骤（需要管理员 PowerShell）

右键「Windows PowerShell」→「以管理员身份运行」，然后：

```powershell
$src = "C:\Users\Windows\AppData\Local\rustdesk"
$dst = "C:\Program Files\RustDesk"

robocopy $src $dst /E /IS /IT /NFL /NDL /NJH /NJS /NP /R:1 /W:1

# 校验
"目录数: " + (Get-ChildItem $dst -Directory -Recurse -Force | Measure-Object).Count
"文件数: " + (Get-ChildItem $dst -File -Recurse -Force | Measure-Object).Count
"app.so 存在: " + (Test-Path "$dst\data\app.so")
```

期望输出：`目录数: 3`（data / drivers / usbmmidd_v2），`文件数: 23` 左右，
`app.so 存在: True`。

## 然后启动程序

```powershell
Stop-Process -Name RustDesk -Force -ErrorAction SilentlyContinue
Start-Process "C:\Program Files\RustDesk\RustDesk.exe"
```

这时应该能看到主界面窗口，任务栏托盘也有图标。

> 注意：`robocopy` 会连 `meta.toml` 和 `store_config.json` 一起复制过去，
> 这两个文件对运行没有影响（`store_config.json` 本来就属于安装目录的一部分），
> 留着也没问题。

## 为什么会出现这个问题

安装流程是：

```
双击安装包
  → 打包器解压到 %LOCALAPPDATA%\rustdesk\
  → 从那里启动 rustdesk.exe --install
  → 安装脚本用 XCOPY 把这个目录复制到 Program Files
```

- 要复制 70MB+ 的文件（librustdesk.dll 40MB、flutter_windows.dll 18MB、app.so 13.8MB），
  **过程中没有任何进度提示**，看起来像卡住了。
- 用户以为卡死，于是再点一次安装（或者重新双击安装包）。
- 打包器随即把解压目录整个删掉 —— Windows 即使在目录被占用时也会**把能删的都删掉**，
  只留下正在运行的那个 exe。
- 正在进行的 XCOPY 源没了，复制到一半失败；但 XCOPY 带着 `/C`（出错也继续），
  **仍然返回 0**，于是安装流程认为「成功」。
- 结果：安装目录缺了 `data\` 等子目录 → Flutter 起不来 → 没有界面。

新包已经修好了这三处：打包器不再在安装进行中清空目录、装完会校验并自动补齐、
以及同一时间只允许一次安装。
