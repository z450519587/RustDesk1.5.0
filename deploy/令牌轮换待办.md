# 令牌轮换待办（需服务器权限）

## 一句话

管理员令牌曾以明文出现在公开仓库的 git 历史里，**必须轮换**。
删文件、改历史都只是「让搜索变难」，唯一彻底的补救是让旧令牌失效。

## 现状

| 项 | 值 |
|---|---|
| 仓库 | `z450519587/RustDesk1.5.0`（**public**） |
| 泄露提交 | `3fbd878`（门店名称同步部署说明）、`e514735`（门店端最终交付说明） |
| 令牌权限 | 等同服务器管理员（可读写 peer 表与 address_book 表） |
| 当前状态 | 文件已打码，但**历史提交里仍在**，`git log -S` 能翻出来 |
| 详细步骤 | `deploy/rotate_admin_token.sql` |

## 谁来做

需要在 **API 服务器**上操作 MySQL（服务在 Docker 里，数据在 `data/` 卷挂载中）。
需要能登进服务器的人执行下面第 1–4 步。

## 步骤

### 服务器上（1–4 步）

- [ ] **1. 拿新令牌**：用管理员账号登录 API 后台复制访问令牌，记作 `NEW_TOKEN`
      （命令行：`curl -X POST https://rd.renhetang.cn:21114/admin/login -H 'Content-Type: application/json' -d '{"username":"<user>","password":"<pass>"}'`）
- [ ] **2. 新令牌永不过期**：`UPDATE user_tokens SET expired_at = 253402300799 WHERE token = 'NEW_TOKEN';`
- [ ] **3. 旧令牌失效**（关键）：`DELETE FROM user_tokens WHERE token = '<旧令牌>';`
      旧令牌从开发机 `deploy/store_config.json` 读（该文件被 gitignore，不在仓库里）
- [ ] **4. 校验**：`SELECT token, expired_at FROM user_tokens WHERE token IN ('<旧令牌>', 'NEW_TOKEN');`
      期望旧令牌那行不存在，新令牌 `expired_at = 253402300799`

### 开发机上（5 步）

- [ ] **5. 更新配置并重新构建**：
      ```
      # 编辑 deploy/store_config.json，把 adminToken 换成新令牌
      # ⚠️ 这个文件被 gitignore 忽略，不要 git add 它
      python deploy/update_store_secret.py          # 刷新 GitHub Secret
      git commit --allow-empty -m "chore: rebuild with the rotated admin token"
      git push origin master                         # 触发构建
      ```
      仓库里的 `deploy/store_settings.json` 不含密钥，无需改动。

### 门店侧（6 步）

- [ ] **6. 分发新包**：旧包的令牌已失效，**旧包的门店名同步会失败**
      （远程连接不受影响，只是门店名不再同步）。
      把新包分发到门店机覆盖安装即可 —— 门店名存在 `%APPDATA%\RustDesk\config\`，
      不在安装目录里，覆盖安装不会丢。

## 校验新包是否带新令牌

```bash
python deploy/inspect_package_config.py <下载的安装包.exe>
```

输出里的 `adminToken` 应该是**新令牌**，`addressBookCollectionId` 应为 `3`。

## 如果暂时不方便轮换

风险可接受的做法：**先把这个仓库改成 private**（Settings → Danger Zone → Change visibility）。
改完令牌就不再对外可见，但轮换仍建议做 —— 因为令牌可能已被搜索引擎收录。
