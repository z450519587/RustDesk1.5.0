# 只允许安装方式运行（不提供绿色版）

## 结论

门店定制版**只以安装方式运行**。不提供、也不允许存在「解压即用 / 绿色版」。
双击安装包 → 弹安装向导 → 装到 Program Files → 写注册表卸载项、建快捷方式、装服务。

## 为什么原来会漏出绿色版

上游 RustDesk 用**文件名**判断「这是不是安装包」：

```rust
pub fn is_setup(name: &str) -> bool {
    !config::is_disable_installation() && name.to_lowercase().ends_with("install.exe")
}
```

文件名是用户可见、可随意改的。于是有三个洞：

| # | 洞 | 触发方式 | 后果 |
|---|---|---|---|
| 1 | 改名即变绿色版 | 把 `rustdesk-1.5.1-install.exe` 改名成 `rustdesk.exe` 再双击 | 不弹安装向导，解压即用 |
| 2 | 安装后残留可执行副本 | 安装完成后 `%LOCALAPPDATA%\rustdesk\` 里还有完整一份 | 拷走就能在别的电脑上跑，卸载项也管不到 |
| 3 | 安装向导的「不安装直接运行」按钮 | 装到一半点那个按钮 | 启动一个 `--noinstall` 实例 |

洞 2 最要紧：即使安装流程正常，装完那一份残留本身就是现成的绿色版。

## 现在的做法

### 1. 定制包靠「标记文件」识别，不靠文件名

打包器（`libs/portable`）和主程序（`src/common.rs`）都改成：
**只要是定制包，一律走安装流程，与文件名无关**。

- 打包器：payload 里有 `store_config.json` 就是定制包
  （`libs/portable/src/main.rs`，常量 `CUSTOM_PACKAGE_MARKER`）
- 主程序：`APP_BRAND_NAME` 是编译期常量「仁和堂专用远程工具」，
  不等于上游的 "RustDesk" 就是定制包
  （`src/common.rs::is_setup`）

> 为什么不复用上游的 `is_custom_client()`？它读的是运行期的 `APP_NAME`，
> 那个值**能被配置项改** —— 用它判定等于留了一条「改配置就变绿色版」的路。
> 必须用编译期常量。

### 2. 关闭「不安装直接运行」入口

- `src/ui/install.tis`：删掉「Run without install」按钮
- `src/ui_interface.rs::run_without_install`：定制包直接拒绝并记日志
- `src/ui_interface.rs::show_run_without_install`：定制包返回 false（不显示按钮）

### 3. `--noinstall` 命令行后门也堵上

`src/core_main.rs` 区分两种来路：

| 来路 | 处理 |
|---|---|
| 用户直接跑 `--noinstall` | 定制包改写成 `--install` —— 强制走安装流程 |
| 安装过程内部的提权重启 `--noinstall --elevate` / `--noinstall --run-as-system` | 原样放行（这是安装流程自己在用，动不得） |

### 4. 安装完成后清掉解压目录

`src/platform/windows.rs::cleanup_portable_extraction_dir`：
装完后起一个后台线程，等安装进程退出再删 `%LOCALAPPDATA%\rustdesk\`。

删得掉吗？能。安装脚本用 XCOPY 把整个目录复制到 Program Files，
Program Files 里那份才是运行的；解压目录删掉不影响使用。

**为什么可以删**：定制版的自动更新是关闭的
（`do_check_software_update` 直接 `Ok(())`，不联网、不提示更新），
没有任何东西依赖这个目录。删不掉也不影响使用 ——
下次运行安装包时打包器的 `setup()` 会因时间戳不匹配整体清掉重来。

## 构建守卫（自动拦截）

`.github/workflows/build-windows-exe.yml` 新增 **Guard the package** 步骤，
每次构建都会跑，三条检查任一不过就中止构建：

1. **产物名必须以 `-install.exe` 结尾** —— 文件名不是 install.exe 就会变绿色版
2. **已跟踪文件里不得含管理员令牌** —— 公开仓库里一次明文提交就是一次泄露
   （`git ls-files` 逐文件 grep 真实令牌）
3. **包里必须带 `store_config.json`** —— 否则门店端拿不到令牌与通讯录 ID

第 2 条就是之前问的「把密钥检查固化进工作流」，已经做了。

## 验证

```bash
python deploy/verify_install_only.py
```

这个脚本把三处判定逻辑（打包器、`is_setup()`、`--noinstall` 处理）镜像成 Python，
跑 18 个场景：改名后的各种文件名、定制包与上游包的区别、提权重启是否被误伤、
端到端「改名 → 仍走安装流程」。

## 注意

- **门店机上如果有旧的绿色版**（10-27 那个 `rustdesk-1.5.1-x86_64.exe`，已被下载 3 次），
  它解压在 `%LOCALAPPDATA%\rustdesk\`。
  **重装新包即可清掉** —— 打包器的 `setup()` 会 `remove_dir_all` 整个清空解压目录再重写，
  新包装完又会把它清掉。不需要手动处理。
  （若门店机没打算重装，手动删 `%LOCALAPPDATA%\rustdesk\` 也行。）
- **令牌轮换仍是待办**（`deploy/令牌轮换待办.md`）。
